    ```markdown
    # Interactive Commands Audit

    **Phase:** 01-audit-and-triage
    **Date:** {today}
    **Auditor:** OpenCode

    ## Classification Key

    | Status | Meaning |
    |--------|---------|
    | stable | Handler is fully implemented, has test coverage, no known issues |
    | broken | Handler has known failure, stub body, or test that documents breakage |
    | uncertain | Handler exists but has no tests and behavior is unverified |
    | experimental | Handler is intentionally partial or behind a feature flag |

    ## Commands

    | Command | Status | Handler File | Line | Evidence | Notes |
    |---------|--------|-------------|------|----------|-------|
    | /example | stable | src/core/services/... | 42 | tests/unit/... passes | ... |
    ...

    ## Summary

    - Stable: N
    - Broken: N
    - Uncertain: N
    - Experimental: N
    - Total: N

    ## Findings

    List any commands that are broken or uncertain with a brief explanation of why.
    ```

    Classification rules:
    - stable: real implementation body + at least one passing test referencing this command
    - broken: stub/TODO/pass body OR a test that explicitly marks it as broken/skipped with a reason
    - uncertain: real-looking implementation but zero test coverage found
    - experimental: explicitly flagged as experimental in code comments or config

    Be conservative: if in doubt between stable and uncertain, classify as uncertain.
  </action>
