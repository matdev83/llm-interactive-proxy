# Implementation Plan

## Process Rules for Implementing Agents

### RTK Source Code Consultation (Mandatory)

The RTK source code at `dev/thrdparty/rtk/` contains proven, well-tested Rust implementations for every compression primitive and tool-specific filter in this plan. **Before implementing any task, agents MUST read the referenced RTK source files** listed in the `_RTK ref:_` annotation of each task. Do not reinvent algorithms, guess at regex patterns, or create ad-hoc heuristics when a working reference exists. Translate patterns faithfully from Rust to Python, adapting only for the proxy's async/DI architecture. The RTK Source Code Reference Map in `design.md` provides a complete file-to-component mapping.

### Test-Driven Development (Mandatory)

All tasks MUST follow strict TDD:
1. **Write failing tests FIRST** - before any production code. Use RTK's inline tests (`#[cfg(test)]` modules) and test fixtures (`dev/thrdparty/rtk/tests/`) as the primary source for realistic test inputs and expected outputs.
2. **Write minimal production code** to make tests pass.
3. **Refactor** while keeping tests green.

Each task's `_RTK ref:_` annotation points to Rust source files that contain both implementation logic AND test cases. Port representative test cases to Python BEFORE implementing the strategy.

### RTK Path Convention

All `_RTK ref:_` paths in this document are relative to `dev/thrdparty/rtk/src/` unless noted otherwise.
